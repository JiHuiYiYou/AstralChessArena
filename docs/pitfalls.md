> 完整的问题↔修法对照表见 `SPEC.md` 末尾；这里只讲「怎么发现」和「怎么避免」。

## A. 原版《星穹弈境》带过来的 20 个 bug

原版是 `legacy/星穹弈境.html`（5041 行单文件浏览器游戏）。
逐条修法见 `SPEC.md` 的「原版 bug 修复对照表」。最容易再犯的几类：

| 症状 | 根因 | 怎么避免 |
|---|---|---|
| 「最终伤害倍数」卡牌加的却是大招倍率 | 属性枚举复制粘贴时错位 | 每加一个属性，都要写一条**能证明它生效**的测试 |
| 初始棋子攻击力超过 1 级上限，第一次升级被悄悄砍掉 | 初始值取了「上限」而不是「模板值」 | 初始值 = 模板值 × 系数；上限只是天花板 |
| 升级撞上限仍收金币、仍涨成本指数 | 上限判定用了「三个属性同时到顶」的与条件 | 任一属性到顶就禁用，并说明是哪个属性 |
| 生命卡只加当前血不加上限 | 加法写在了 `hp` 上，`maxHp` 漏了 | 生命类改动必须同时动 `hp` 与 `maxHp` |
| 闪避判定在连击链之后，日志打出不存在的暴击 | 结算顺序反了 | **先判闪避，再算连击链** |
| 取消锻造弹窗吞掉金丹 | 扣资源写在「打开弹窗」而不是「确认」 | 扣资源一律放在确认动作里 |
| 升阶取所有属性的平均值 | 「合并」写成了求平均 | 升阶用「取大 + 小的 50%」 |
| 100 回合超时判负 | 超时被归到失败分支 | 超时判**平局** |
| 布阵整条链路是死代码 | 按钮从来没被渲染过 | 每个功能都要有一条端到端的路可走 |
| 只有三处 autosave | 存盘点手写而非统一事务 | 所有写操作同事务落盘 |
| 敌方只缩放血和攻击 | 敌方阵容只改了两个数 | 敌方的等级/星级/装备/羁绊要一起成长 |
| 声称按速度排序但没有 speed 字段 | 文档写了，代码没写 | 文档说有的东西，代码里就得有 |
| 处决慢镜头污染了持久化的 battleSpeed | UI 效果改了玩家设置 | UI 效果用独立变量 |
| 敌方阶段是友方阶段 60 行复制粘贴 | 复制粘贴驱动开发 | 一个 `runPhase(side)` 两侧共用 |

## B. 本项目自己踩的坑（移植过程中）

### B1. SQL 漏传参数 → 查询静默返回空

```js
queryAll(`SELECT ... WHERE save_id = ?`)      // ← 忘了 , saveId
```

SQLite 会把占位符绑成 NULL，**不报错**，查询安静地返回空数组。
表现是「商店永远是空的」这种幽灵 bug。

**现在 `queryAll` / `queryOne` 会校验占位符数量，对不上直接抛错。**

### B2. 字段名 camelCase / snake_case 混用 → 属性算成 NaN

`metaRepo.getTemplate()` 返回 camelCase，而 `createPiece` 期望 snake_case，
于是 `template.base_attack` 是 `undefined` → 属性算成 NaN → 绑进 SQLite 时报
「NOT NULL constraint failed」，**报错信息完全指不到真正的原因**。

**规矩：JS 侧一律 camelCase，只有 SQL 列名是 snake_case。**

### B3. 模板字段（code / glyph / 职业）没存进表

`save_heroes` 只存了 `template_id`，战斗和羁绊都需要 `code` / `glyph` / 职业。
解法：`listHeroes` / `getHero` **JOIN** 模板表与职业表，不要冗余存字段。

### B4. `resetBoard` 把格子也删了

棋盘的 64 个格子是提前建好的，重开战斗时只该删棋子。
结果战斗棋盘没有格子 → 一个棋子都渲染不出来。

### B5. 事件时间戳每回合被「重置」

`ctx.log.t = (r - 1) * T_ROUND` 会让时间戳倒退（一回合的事件时长超过回合长度），
前端按 delta 播放就会出现负延迟。

**回合起点要接在上一回合最后一个事件之后。**

### B6. 暴击倍率跟着等级系数一起涨

5 级马的暴击倍率到 7.3 倍，一击秒掉同级王。详见 `docs/balance.md` 第 1 节。

### B7. 四种功能性大招也乘伤害倍率

一次大招秒掉同级单位。详见 `docs/balance.md` 第 2 节。

### B8. 护盾没有上限 → 无限僵持

「铁壁反击」每 4 回合加一大片护盾，而每回合伤害打不穿 →
40 回合里 90 次攻击有 70 次伤害为 0。详见 `docs/balance.md` 第 3 节。

### B9. 敌方阵容随机抽 → 难度曲线剧烈抖动

抽到「后+王」和抽到「兵+马」强度差接近一倍。改成按章节固定 lineup。

### B10. 敌方等级跟着玩家回合数涨

玩家等级涨得比回合慢，于是第 2 章直接打不过。敌方等级只跟章节走。

### B11. 数组字段名写错导致事件缺字段

`attack` 事件里补 `name: attacker.name` 时，只改到了「闪避」分支，
主攻击分支漏了 —— 战斗日志里攻击者名字一直是空的。
**改事件结构时要把所有 `log.push('attack', ...)` 都过一遍。**

### B12. 浮点数没取整

大招倍率显示成 `×3.4700000000000006`。事件里的数字对外一律 `toFixed(2)`。

### B13. 标签页的 handler 忘了定义

`onSelectHero` 没写 → 「阵容」标签页整个不渲染，而且**控制台报错被淹没**，
截图里看起来「内容没切换」。

**加完 handler 要在浏览器里把每个标签页点一遍。**

### B14. `jj` 会自动进分页器并吃掉输入

本机 jj 的 `jj log` / `jj op log` 输出长了会自动进 less，之后敲的命令被分页器吃掉，
屏幕上还会冒 `invalid digit found in string` 之类的假报错。
**所有 jj 命令一律加 `--no-pager`。**

### B15. `jj bookmark set` 之后忘了推

`jj describe` + `jj new` 只改了工作副本，**`main` 书签还指向上一次提交**，
`jj git push` 会报「Nothing changed」。
推之前先 `jj log --no-pager` 确认 `main` 指向你要推的那个提交。

### B16. 端口 5173 已被本机的 Vite 占用

那个 Vite 绑在 **IPv6 的 ::1** 上，本项目绑在 IPv4 的 127.0.0.1。
浏览器访问 `localhost:5173` 会命中 Vite 而不是本项目。
**默认端口改成 5180，并且打印 `http://127.0.0.1:<port>/` 而不是 `localhost`。**

### B17. `node --test test/` 找不到测试

要写成 `node --test "test/*.test.js"`。且 `package.json` 必须有 `"type": "module"`，
否则 `import` 直接语法错误。

### B18. `node:sqlite` 会打印实验性警告

启动脚本加 `--disable-warning=ExperimentalWarning`。

### B19. jj 拒绝快照大文件

2.4 MB 的 docx 超过默认的 1 MB 上限。
`jj config set --repo snapshot.max-new-file-size 8388608`。

### B20. 文档生成时把别的作业的会话也收了进来

同一个工作目录下还有另外两个作业的会话（JHYY 介绍页、jj 回退作业）。
`tools/build-doc.mjs` 现在会按「cwd 在本工作目录内 **且** 首条提示词命中本项目关键词」
双重过滤。
