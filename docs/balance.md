# docs/balance.md —— 数值与平衡调参规约

> 改数值前先读这一份。**所有数值都在 `src/core/balance.js`**，不要散落到别处。
> 改完必须跑 `npm test` + `npm run balance`。

---

## 1. 两套成长系数

```
lvScale(L)   = 1.35^(L-1)      攻击 / 生命 —— 升级让你「更大」
critScale(L) = 1 + 0.035(L-1)  暴击率 / 暴击倍率 / 大招倍率 —— 升级让你「不更狠」
defScale(L)  = 1 + 0.08(L-1)   防御 / 闪避
softScale(L) = 1 + 0.12(L-1)   回复
```

初始值 = 模板基础值 × 对应系数（**不是上限**）；上限 = 模板基础值 × 对应系数 × 4。

### 为什么暴击类属性不能跟等级系数一起涨

实测过：暴击倍率跟着 `1.35^L` 涨时，5 级的马暴击倍率会到 **7.3 倍**，
一次暴击 3632 伤害直接秒掉 6276 血的敌方王 —— 战斗变成掷骰子，
而且「第 5 章 1 回合结束」。

**暴击锐度交给突破 / 装备 / 卡牌去堆，升级只负责把棋子做大。**

## 2. 大招：只有两种是「伤害型」

| 棋子 | 大招 | 伤害型 |
|---|---|---|
| 兵 | 战地鼓舞（治疗 + 护盾） | ✗ |
| 马 | 影刃连斩（追加一次攻击） | ✓ |
| 主教 | 奥术穿透（无视 50% 防御） | ✗ |
| 车 | 铁壁反击（护盾 + 嘲讽 + 反弹） | ✗ |
| 后 | 群星陨落（全体敌人） | ✓ |
| 王 | 王之守护（全体减伤） | ✗ |

只有马和后的大招乘伤害倍率。其余四种是功能性大招，
乘了倍率就是「一次大招秒掉同级单位」—— 那是数值失衡，不是爽感。

---

## 3. 护盾必须有上限

- 护盾上限 = **最大生命 × 25%**。
- 护盾被打碎 → 攻击方下一次打这个目标**伤害 +30%**（只生效一次）。

没有上限时，「铁壁反击」每 4 回合给 25% 最大生命的护盾，
而每回合伤害只有 ~85 —— 护盾永远打不穿，两个车一直僵持到超时。
实测：40 回合里 90 次攻击有 70 次伤害为 0。

---

## 4. 敌方阵容：按章节固定，不要随机

随机抽会让难度曲线剧烈抖动（抽到「后+王」和抽到「兵+马」强度差接近一倍）。

| 章节 | 敌方阵容 | 装备 |
|---|---|---|
| 1 | 兵、兵 | — |
| 2 | 兵、马 | — |
| 3 | 马、车、兵 | — |
| 4 | 马、车、主教、兵 | 暴击爪 |
| 5 | 王、马、车、主教 | 疾风、暴击爪 |
| 6 | 王、马、车、主教、兵 | 暴击爪、护盾发生器 |
| 7 | 后、王、马、车、主教 | 暴击爪、破甲 |
| 8 | 后、王、后、马、车 | 暴击爪、破甲、血怒 |

- 敌方等级 = **章节数**（不跟玩家回合数走 —— 玩家等级涨得比回合慢）。
- 敌方从第 5 章起必定有一个王，否则「将死」永远触发不了。
- 敌方同样吃羁绊加成。

## 5. 怎么验证

```bash
npm run balance          # 跑批量战斗，按章节统计胜率
npm run balance 10 100  # 10 章，每章 100 局
```

模拟会按「玩家在该章节应有的状态」构造我方阵容：
**等级 = 章节，棋子数 = 2 + 章节/2（上限 5），装备与敌方同量，棋子顶到前线（rank 2-3）**。

目标曲线：

| 章节 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 期望胜率 | ~80% | ~75% | ~60% | ~50% | ~40% | ~35% | ~30% | ~25% |

**胜率要随章节平缓下降**，不能第一章就崩，也不能一路平躺。

调参顺序建议：
1. 先改敌方 lineup / 装备 / 等级 → 影响「难度形状」
2. 再改基础攻防 → 影响「战斗长度」（目标 8~15 回合）
3. 最后改上限与系数 → 影响「成长天花板」

**不要凭感觉改数字** —— 改完跑一遍 `npm run balance` 看曲线。

## 6. 其它容易踩的数值坑

- **初始值不能取上限**：初始值 = 模板值 × 系数。上限是天花板，不是起点。
- **训练撞上限要直接禁用并说明**，不要收下金币再夹回去（会白吞资源）。
- **升阶用「取大 + 小的 50%」再乘等级系数比**，不要用平均值。
  只用前半段的话，两个同级棋子合成一个总属性从 2A 掉到 1.5A —— 升阶成了陷阱
  （自动通关模拟实测：模拟玩家在第 3 章反复卡住）。
- **突破要同步抬高该属性的上限**（记绝对下限 = 当前值 ×1.05，**不要用乘数**），
  否则突破涨上去立刻被夹回去，等于白花资源。
- **每个属性最多突破 3 次**。突破要是能无限叠，一个 1 级棋子的攻击能堆到 38000，
  其它养成全部失去意义。
- **生命类卡牌要同时改 `maxHp` 与 `hp`**，否则血条会超过 100%。
- **模板字段名统一 camelCase**（只有 SQL 列名是 snake_case）—— 混用会把属性算成 NaN，
  而且 NaN 绑进 SQLite 表现为「NOT NULL constraint failed」，很难查。

### 突破的上限要用「绝对下限」，不能用乘数

原实现里每次突破把该属性的上限 `× 1.5`。于是上限也跟着突破次数指数膨胀：
20 次突破 = 1.5^20 ≈ 3300 倍，一个 1 级棋子的攻击能到 38000，
所有其它养成都失去意义。

改成记**绝对下限**（当前值 × 1.05）之后：上限只跟着数值走，
突破永远是「涨上去且不会被夹回来」，同时用「每个属性最多 3 次」限制总量。
