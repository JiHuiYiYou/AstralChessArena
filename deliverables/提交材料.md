## 一、项目简介

把国际象棋的走法搬进自走棋：8×8 棋盘上，英雄按国际象棋六种棋子的走法自动走位与攻击，
外层套上自走棋的商店、经济、羁绊、装备与养成循环。

- **后端**：NodeJS（`node:http` + 内置 `node:sqlite`），零运行时依赖，规范化表结构，10 张表。
- **前端**：浏览器原生 ES module，无打包器。棋盘增量渲染，战斗由服务端产出**带时间戳的事件流**、前端按时间轴播放。
- **传统机制**：兵升变、将军/将死、王车易位、吃过路兵、蹩马腿、终局和棋。
- **自走棋机制**：商店与刷新、回合经济（基础收入/连胜连败/存款利息）、职业羁绊（2/4/6 件三档）、装备、章节难度。
- **数值取向**：割草膨胀。无界暴击连击链 + 破防 + 护盾 + 最终伤害倍率 + 大招倍率 + 残血处决。
- **打击感**：屏幕震动（按伤害量级分 4 档）、命中顿帧、分级伤害飘字、连击横幅、处决十字斩、将死全屏黑闪，外加程序化 WebAudio 音效。

由原版单文件浏览器游戏《星穹弈境》（5041 行，localStorage 存档）重写而来，
原版保留在 `legacy/` 供对照，移植过程中修掉了它 **20 个已确认的 bug**（见附录 SPEC.md 的对照表）。

|---|---|
| **国际象棋** | 六种棋子的走法与阻挡规则、蹩马腿、兵升变、将军/将死、王车易位、吃过路兵、终局和棋 |

## 1. 术语

| 准备阶段 | 玩家操作：商店、布阵、养成 |
| 战斗阶段 | 服务端算完整场战斗，前端播放事件流 |
| 上阵 / 下场 | 棋子是否在棋盘上（只有上阵的棋子参战） |

| 星级 (star) | 展示用，`min(5, ceil(level/2))` |

## 2. 棋盘与坐标

- 8×8 棋盘，坐标 `file 0-7`（a-h）× `rank 0-7`（1-8）。
- **己方半场**：`rank 0-3`（下 4 排）；**敌方半场**：`rank 4-7`（上 4 排）。
- 渲染时 DOM 顺序为 rank 7 → 0，所以屏幕上敌在上、我在下。
- 棋盘索引 = `rank * 8 + file`。
- 每方最多上阵 **5** 个棋子。

|---|---|---|---|---|---|---|---|---|---|---|---|
| 兵 | `pawn` | ♟ | 圣疗者 | 前 1 格；**首动**可前 2 格 | 斜前 1 格 | 75 | 1000 | 3 | 5% | 1.4 | 1.5 |
| 马 | `knight` | ♞ | 影刃 | 日字 8 格，受**蹩马腿**限制 | 同移动 | 120 | 1000 | 8 | 35% | 2.2 | 1.6 |
| 主教 | `bishop` | ♝ | 奥术师 | 斜线任意格，路径不可穿越 | 同移动 | 110 | 900 | 5 | 20% | 2.0 | 2.2 |
| 车 | `rook` | ♜ | 铁卫 | 横竖直线，路径不可穿越 | 同移动 | 115 | 1300 | 3 | 10% | 1.6 | 1.6 |
| 后 | `queen` | ♛ | 奥术师 | 八方向任意格，路径不可穿越 | 同移动 | 150 | 1100 | 6 | 25% | 2.4 | 1.8 |
| 王 | `king` | ♚ | 铁卫 | 八邻 1 格 | 八邻 | 85 | 1400 | 2 | 10% | 1.8 | 1.5 |

**通用规则**

- 移动落点必须为空；吃子只能吃敌方棋子。
- 滑行类（主教/车/后）被阻挡时不能穿越。
- **蹩马腿**：马走 `(±1,±2)` 或 `(±2,±1)` 时，两个拐角 `(file+sign(df), rank)` 与 `(file, rank+sign(dr))`
  任意一个有子就不能跳。
- **升变**：兵走到对方底线（白 rank 7 / 黑 rank 0）自动升变，候选为该兵模板的 `promoteTo` 列表
  （兵 → 马 / 主教 / 车），按 实用度 车 > 主教 > 马 排序。升变后属性取「新旧的最大值」。
- **吃过路兵**：本方兵两格推进后的**紧接一个己方回合**，可斜吃刚越过的敌兵。
  - 白兵在 rank 4，黑兵刚从 rank 6 走到 rank 4 → 白兵可落到 rank 5 吃掉它。
  - 黑兵在 rank 3，白兵刚从 rank 1 走到 rank 3 → 黑兵可落到 rank 2 吃掉它。
  - 用 `lastDoubleStep` 标记，一回合后失效。
- **王车易位**：王与车都未动过、车与王之间无子、王当前与途经的格子都不被攻击时可用。
  一次把王挪 2 格、车挪 1 格。**AI 只在附近 3 格无敌子时使用。**

## 4. 属性与成长

### 4.1 属性

`attack` / `hp` / `maxHp` / `speed` / `critRate` / `critMult` / `ultMult` / `ultCd` /
`defense` / `dodge` / `recovery` / `shield` / `finalDamageMult`

### 4.2 等级系数与上限

``​`
lvScale(L)   = 1.35^(L-1)      攻击 / 生命 —— 升级让你「更大」
critScale(L) = 1 + 0.035(L-1)  暴击率 / 暴击倍率 / 大招倍率 —— 升级让你「不更狠」
defScale(L)  = 1 + 0.08(L-1)   防御 / 闪避
softScale(L) = 1 + 0.12(L-1)   回复

初始属性 = 模板基础值 × 对应系数        （不是上限！）
属性上限 = 模板基础值 × 对应系数 × 4
``​`

> **为什么暴击类属性不跟着 1.35^L 涨？**
> 实测过：暴击倍率跟着等级系数涨时，5 级的马暴击倍率会到 7.3 倍，
> 一击暴击 3632 伤害直接秒掉 6276 血的敌方王 —— 战斗变成掷骰子，
> 而且「第 5 章 1 回合结束」。把暴击锐度交给**突破 / 装备 / 卡牌**去堆，
> 升级只负责把棋子做大，战斗才有来有回。

硬上限（与等级无关）：

| 属性 | 上限 | | 属性 | 上限 |
|---|---|---|---|---|
| critRate | 0.80 | | defense | 0.60 |
| critMult | 10 | | dodge | 0.50 |
| ultMult | 10 | | finalDamageMult | 5 |

突破会额外把**该属性的上限**乘 1.5（见 5.3），所以突破永远不会「涨了又被夹回去」。

### 4.3 训练

- 在当前等级内变强：攻击/生命/暴击倍率/大招倍率 **×1.12**，暴击率/防御/闪避 **×1.03**。
- 成本 `floor(10 × 1.2^(L-1) × 1.15^训练次数)`。
- **任一受影响属性已到上限 → 禁止训练并说明是哪个属性**，不扣钱。
- 训练**不提升等级**；想继续变强必须升阶。

### 4.4 升阶（融合）

- 消耗 **2 个同种棋子** + 金币 `20 + 等级×10`。
- 属性公式（**不是平均值**）：

``​`
合并值 = max(a, b) + floor(min(a, b) × 0.5)
新属性 = floor(合并值 × 等级系数比)      等级系数比 = 1.35^(新等级-1) / 1.35^(旧等级-1)
新等级 = max(等级) + 1
新星级 = min(5, max(星级) + 1)
``​`

> **为什么还要乘等级系数比？**
> 只按「取大 + 小的 50%」的话，两个同级棋子合成一个，**总属性从 2A 掉到 1.5A** ——
> 玩家白白损失一个身位还变弱，升阶成了陷阱（自动通关模拟里实测到了）。
> 乘上等级系数比之后，两个同级棋子合成一个总属性 ≈ 2A（还略高一点），
> 身位少一个但等级 +1（上限 ×1.35），这才是「升级」该有的感觉。

- 暴击率 / 暴击倍率 / 大招倍率 / 防御 / 闪避 / 速度等取**强的那一边**。
- 升阶保留站位、装备、突破加成。

### 4.5 突破

- 消耗金币 `floor(25 × 1.35^(L-1))`。
- 选择一个属性，**×1.30 ~ ×1.60**（随机）。
- **每个属性最多突破 3 次**（首次突破锁定属性，之后沿用）。
- 突破同时把该属性的**上限抬到「当前值 × 1.05」**——
  记的是**绝对下限**而不是乘数。乘数会让上限跟着突破次数指数膨胀
  （20 次突破 = 1.5^20 倍，实测能把一个 1 级棋子的攻击堆到 38000）。
  记绝对下限就只跟数值走，突破永远不会「涨上去又被夹回来」。

### 4.6 附魔（卡牌）

10 种属性 × `+` / `×` 两种操作：

| 属性 | 加法范围 | 乘法范围 |
|---|---|---|
| 基础攻击力 | 0 ~ 40 | ×1.00 ~ 1.40 |
| 暴击率 | 0 ~ 0.08 | ×1.00 ~ 1.30 |
| 暴击倍率 | 0 ~ 1.5 | ×1.00 ~ 1.30 |
| 回复 | 0 ~ 40 | ×1.00 ~ 1.30 |
| 生命 | 0 ~ 250 | ×1.00 ~ 1.25 |
| 大招倍率 | 0 ~ 1.5 | ×1.00 ~ 1.30 |
| 大招冷却 | -1 ~ 0（降低） | ×1.00 ~ 1.25（降低） |
| 防御系数 | 0 ~ 0.05 | ×1.00 ~ 1.30 |
| 闪避系数 | 0 ~ 0.04 | ×1.00 ~ 1.30 |
| **最终伤害倍数** | 0 ~ 0.5 | ×1.00 ~ 1.25 |

- **生命类卡同时改 `maxHp` 与 `hp`**，且 `hp ≤ maxHp` 恒成立。
- 撞上限导致「一点没涨」时直接报错，不扣钱。

## 5. 战斗结算

### 5.1 伤害结算顺序（`src/core/combat.js`）

``​`
① 闪避判定 —— 整条连击链一起判。被闪避则**不产生任何暴击数字**
② 连击链
     damage = 攻击
     循环：
       若 暴击：
         波动 = 1.0 + rand×0.5                // [1.0, 1.5)
         本次 = 波动 × 暴击倍率 × damage
         若 波动 > 1.2 → 连击层数 +1，继续循环
       否则：
         本次 = damage（非暴击），结束循环
     超过 12 层的部分，每多一层 ×0.85
③ 破防：对同一目标连续命中 +34，满 100 → 目标防御归零 3 回合
④ 破盾加伤：上一击打碎了目标的护盾 → 本击伤害 ×1.3（只生效一次）
⑤ 护盾：先扣护盾，溢出部分才扣血
     护盾上限 = 最大生命 × 25%（超过会被截断）
     护盾被打碎 → 攻击方获得一次「破盾加伤」
⑥ 防御：扣血 = 总伤害 × (1 - 防御)，可被「破甲」穿透 20%、被主教大招再无视 50%
⑦ 最终伤害倍数：扣血 ×= finalDamageMult
⑧ 大招倍率：**只有伤害型大招**（马 / 后）才乘，大招倍率 ×= ultMult
⑨ 处决：目标剩余生命 < 最大生命 × 15% → 直接斩杀，**无视护盾**
``​`

> **护盾为什么要有上限？**
> 没有上限时，「铁壁反击」每 4 回合给 25% 最大生命的护盾，
> 而每回合伤害只有 ~85 —— 护盾永远打不穿，两个车会一直僵持到超时。
> 实测：40 回合里 90 次攻击有 70 次伤害为 0。护盾上限 25% + 破盾加伤解决了这个问题。

期望单次伤害（用于展示战力）：

``​`
E[伤害] = 攻击 × ((1 - c) + 1.25·c·暴击倍率) / (1 - 0.6·c)
``​`

### 5.2 大招

冷却 `ultCd` 回合。战斗开始时 `ultCooldown = 1`，每个己方回合末 `-1`，归零时可发动。
发动后 `ultCooldown = ultCd`。

| 棋子 | 大招 | 效果 | 伤害型 |
|---|---|---|---|
| 兵 | 战地鼓舞 | 治疗全体友军（回复 ×2）并给 8% 最大生命的护盾 | ✗ |
| 马 | 影刃连斩 | 本次攻击带大招倍率，**并追加一次普通攻击** | ✓ |
| 主教 | 奥术穿透 | 本次攻击无视目标 50% 防御 | ✗ |
| 车 | 铁壁反击 | 获得 12% 最大生命的护盾，2 回合内**嘲讽**并反弹 30% 伤害 | ✗ |
| 后 | 群星陨落 | 对**全体敌人**造成大招倍率伤害 | ✓ |
| 王 | 王之守护 | 全体友军 3 回合内减伤 10% | ✗ |

> **只有马和后的大招乘伤害倍率。** 其余四种是功能性大招（治疗 / 穿透 / 护盾 / 减伤），
> 如果也乘倍率，一次大招就能把同级单位秒掉 —— 那是数值失衡，不是爽感。

### 5.3 回合结构

``​`
准备阶段（玩家操作，不计回合）
战斗阶段：
  for round in 1..40:
     己方阶段：按 speed 降序，每个存活棋子行动一次
        行动 = ①被动治疗 → ②大招判定 → ③若攻击范围内有敌人 → 攻击
              → ④否则王车易位 / 吃过路兵 / 向最近敌人合法移动 1 格
              → ⑤移动后若能打到人 → 立即追加一次攻击
     敌方阶段：同上（`runPhase(side)`，两侧共用同一份代码）
     回合末：破防剩余 -1、减伤 -1、嘲讽 -1、大招冷却 -1
结束条件：一方王陨落（将死） / 一方全灭 / 到达 40 回合 → **判平局**
``​`

**目标评分**（越高越优先打）：

**落点评分**：

| 项 | 分值 |
|---|---|

| 其中能斩杀的 × 420 | + |
| 其中是王的 × 500 | + |
| 到最近敌人的切比雪夫距离 × 55 | − |

### 5.5 敌方阵容生成

**按章节固定 lineup + 固定装备**（随机抽会让难度曲线剧烈抖动 ——
抽到「后+王」和抽到「兵+马」强度差接近一倍）：

| 章节 | 敌方阵容 | 装备 |
|---|---|---|
| 1 | 兵、兵 | — |
| 2 | 兵、马 | — |
| 3 | 马、车、兵 | — |
| 4 | 马、车、主教、兵 | 暴击爪 |
| 5 | 王、马、车、主教 | 疾风、暴击爪 |
| 6 | 王、马、车、主教、兵 | 暴击爪、护盾发生器 |
| 7 | 后、王、马、车、主教 | 暴击爪、破甲 |
| 8 | 后、王、后、马、车 | 暴击爪、破甲、血怒 |

## 7. 经济与商店

``​`
回合收入 = 基础 8
         + 连胜奖励 min(12, 2 + 连胜数)      （连败时 min(8, 2 + 连败数)）
         + 利息 min(10, floor(金币 × 10%))
胜利奖金 = 20 + 章节 × 10
平局/失败 = floor(基础收入 × 0.5)
``​`

- 商店 5 槽，每回合**免费刷新 1 次**，之后 2 金/次。
- 槽位构成：**10% 随机卡牌**、**18% 装备**、其余是棋子（权重随章节变化：王/后概率随章节上升）。
- 棋子价格 `2 + round(基础攻击/18) + round(基础生命/160) + 已有同种数量`。
- 装备价格按稀有度：普通 12 / 稀有 20 / 史诗 32。
- 卖出返还 `1 + 星级`（必须先下场）。
- **装备流程**：商店买到 → 进装备背包（`save_items` 表）→ 在阵容面板点装备 → 选棋子装上 → 从背包移除。

### 7.1 章节选择

- 存档带 `chapter`（当前挑战的章节）与 `max_chapter`（已解锁的最高章节）。
- 胜利后 `chapter + 1`（封顶 12），并把 `max_chapter` 推到相同位置。
- 玩家可以在准备阶段点章节按钮任选 `≤ max_chapter` 的章节 —— **可以回头刷旧章节**。
- 越往后敌方越强：`等级 = 1 + floor(章节×0.9) + floor(玩家回合×0.25)`，
  `生命系数 = 1 + 0.18×(章节-1)`，`攻击系数 = 1 + 0.22×(章节-1)`，
  敌方棋子数 `min(5, 2 + floor(章节/2))`，星级 `min(5, 1+floor(章节/3))`，装备 `min(3, floor(章节/2))`。

## 8. 战斗事件流

服务端算完整场战斗，产出**带时间戳的事件数组**；前端按 `t` 的差值播放，
速度可调（0.5× / 1× / 2× / 4×）或直接跳过。

事件类型：

| 事件 | 关键字段 |
|---|---|
| `battle_start` | `ally[]`、`enemy[]`、`allyPower`、`enemyPower` |
| `round_start` | `round` |
| `move` | `side`、`id`、`kind`(`normal`/`castle`/`en_passant`)、`from`、`to` |
| `skill` | `side`、`id`、`name`、`desc`、`mult` |
| `attack` | `side`、`id`、`name`、`target`、`targetName`、`damage`、`crit`、`combo`、`rawDamage`、`shieldAbsorbed`、`brokeDefense`、`execute`、`ult`、`hpBefore`、`hpAfter`、`maxHp` |
| `heal` | `side`、`id`、`amount`、`hpAfter` |
| `promotion` | `side`、`id`、`code`、`name`、`glyph` |
| `execute` | `side`、`id`、`name`、`killer` |
| `death` | `side`、`id`、`name` |
| `checkmate` | `side`、`id`、`name` |
| `round_end` | `round` |
| `battle_end` | `result`(`win`/`lose`/`draw`)、`rounds`、`reason` |

时间戳**单调不减**（下一回合的起点接在上一回合最后一个事件之后）。

# docs/balance.md —— 数值与平衡调参规约

> 改数值前先读这一份。**所有数值都在 `src/core/balance.js`**，不要散落到别处。
> 改完必须跑 `npm test` + `npm run balance`。

## 1. 两套成长系数

``​`
lvScale(L)   = 1.35^(L-1)      攻击 / 生命 —— 升级让你「更大」
critScale(L) = 1 + 0.035(L-1)  暴击率 / 暴击倍率 / 大招倍率 —— 升级让你「不更狠」
defScale(L)  = 1 + 0.08(L-1)   防御 / 闪避
softScale(L) = 1 + 0.12(L-1)   回复
``​`

初始值 = 模板基础值 × 对应系数（**不是上限**）；上限 = 模板基础值 × 对应系数 × 4。

### 为什么暴击类属性不能跟等级系数一起涨

实测过：暴击倍率跟着 `1.35^L` 涨时，5 级的马暴击倍率会到 **7.3 倍**，
一次暴击 3632 伤害直接秒掉 6276 血的敌方王 —— 战斗变成掷骰子，
而且「第 5 章 1 回合结束」。

**暴击锐度交给突破 / 装备 / 卡牌去堆，升级只负责把棋子做大。**

---

## 2. 大招：只有两种是「伤害型」

| 棋子 | 大招 | 伤害型 |
|---|---|---|
| 兵 | 战地鼓舞（治疗 + 护盾） | ✗ |
| 马 | 影刃连斩（追加一次攻击） | ✓ |
| 主教 | 奥术穿透（无视 50% 防御） | ✗ |
| 车 | 铁壁反击（护盾 + 嘲讽 + 反弹） | ✗ |
| 后 | 群星陨落（全体敌人） | ✓ |
| 王 | 王之守护（全体减伤） | ✗ |

只有马和后的大招乘伤害倍率。其余四种是功能性大招，
乘了倍率就是「一次大招秒掉同级单位」—— 那是数值失衡，不是爽感。

---

## 3. 护盾必须有上限

- 护盾上限 = **最大生命 × 25%**。
- 护盾被打碎 → 攻击方下一次打这个目标**伤害 +30%**（只生效一次）。

没有上限时，「铁壁反击」每 4 回合给 25% 最大生命的护盾，
而每回合伤害只有 ~85 —— 护盾永远打不穿，两个车一直僵持到超时。
实测：40 回合里 90 次攻击有 70 次伤害为 0。

---

## 4. 敌方阵容：按章节固定，不要随机

随机抽会让难度曲线剧烈抖动（抽到「后+王」和抽到「兵+马」强度差接近一倍）。

| 章节 | 敌方阵容 | 装备 |
|---|---|---|
| 1 | 兵、兵 | — |
| 2 | 兵、马 | — |
| 3 | 马、车、兵 | — |
| 4 | 马、车、主教、兵 | 暴击爪 |
| 5 | 王、马、车、主教 | 疾风、暴击爪 |
| 6 | 王、马、车、主教、兵 | 暴击爪、护盾发生器 |
| 7 | 后、王、马、车、主教 | 暴击爪、破甲 |
| 8 | 后、王、后、马、车 | 暴击爪、破甲、血怒 |

- 敌方等级 = **章节数**（不跟玩家回合数走 —— 玩家等级涨得比回合慢）。
- 敌方从第 5 章起必定有一个王，否则「将死」永远触发不了。
- 敌方同样吃羁绊加成。

---

## 5. 怎么验证

``​`bash
npm run balance          # 跑批量战斗，按章节统计胜率
npm run balance 10 100  # 10 章，每章 100 局
``​`

模拟会按「玩家在该章节应有的状态」构造我方阵容：
**等级 = 章节，棋子数 = 2 + 章节/2（上限 5），装备与敌方同量，棋子顶到前线（rank 2-3）**。

目标曲线：

| 章节 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 期望胜率 | ~80% | ~75% | ~60% | ~50% | ~40% | ~35% | ~30% | ~25% |

**胜率要随章节平缓下降**，不能第一章就崩，也不能一路平躺。

调参顺序建议：
1. 先改敌方 lineup / 装备 / 等级 → 影响「难度形状」
2. 再改基础攻防 → 影响「战斗长度」（目标 8~15 回合）
3. 最后改上限与系数 → 影响「成长天花板」

**不要凭感觉改数字** —— 改完跑一遍 `npm run balance` 看曲线。

---

## 6. 其它容易踩的数值坑

- **初始值不能取上限**：初始值 = 模板值 × 系数。上限是天花板，不是起点。
- **训练撞上限要直接禁用并说明**，不要收下金币再夹回去（会白吞资源）。
- **升阶用「取大 + 小的 50%」再乘等级系数比**，不要用平均值。
  只用前半段的话，两个同级棋子合成一个总属性从 2A 掉到 1.5A —— 升阶成了陷阱
  （自动通关模拟实测：模拟玩家在第 3 章反复卡住）。
- **突破要同步抬高该属性的上限**（记绝对下限 = 当前值 ×1.05，**不要用乘数**），
  否则突破涨上去立刻被夹回去，等于白花资源。
- **每个属性最多突破 3 次**。突破要是能无限叠，一个 1 级棋子的攻击能堆到 38000，
  其它养成全部失去意义。
- **生命类卡牌要同时改 `maxHp` 与 `hp`**，否则血条会超过 100%。
- **模板字段名统一 camelCase**（只有 SQL 列名是 snake_case）—— 混用会把属性算成 NaN，
  而且 NaN 绑进 SQLite 表现为「NOT NULL constraint failed」，很难查。

### 突破的上限要用「绝对下限」，不能用乘数

原实现里每次突破把该属性的上限 `× 1.5`。于是上限也跟着突破次数指数膨胀：
20 次突破 = 1.5^20 ≈ 3300 倍，一个 1 级棋子的攻击能到 38000，
所有其它养成都失去意义。

改成记**绝对下限**（当前值 × 1.05）之后：上限只跟着数值走，
突破永远是「涨上去且不会被夹回来」，同时用「每个属性最多 3 次」限制总量。

```

## 2. 三条铁律

### ① 不要 `innerHTML` 全量重绘

棋子元素按 id 缓存复用（`render/board.js` 的 `pieceIndex`）：

- 血条**只改 `style.width`**，不重建元素 —— 否则 CSS 的 `transition` 失效，血条「啪」地跳。
- 动效**只加/删 class**，不重建节点 —— 否则正在播的动画会被下一次渲染冲掉。
  （这是原版最大的架构病：`innerHTML` 全量重绘把 `attacking` / `taking-damage` /
  组合斩 / 伤害飘字全部打断。）

### ② 动画只动 `transform` / `opacity` / `filter`

不要动 `top` / `left` / `width` / `height`，也不要动 `letter-spacing`
（它会触发 layout）。飘字用 `transform: translate(-50%, -50%)` 起步，
动画里只改 `translateY` / `scale` / `opacity`。

### ③ 战斗是「事件流播放」，不是「边算边画」

服务端算完整场战斗 → 产出带时间戳的事件数组 → 前端按 `t` 的差值播放。
前端**不参与战斗计算**。

好处：
- 动画不会被下一次渲染冲掉。
- 速度可调（0.5×/1×/2×/4×）与「跳过」都不影响结果。
- 战斗可以存进 `battles` 表回看 —— 回放用的是同一个播放器，观感完全一致。

2. 在 `public/js/battle/vfx.js` 里加一个导出函数：**加 class → setTimeout 移除**。
3. 在 `public/js/battle/player.js` 的事件处理里调用它。

不要在业务代码里直接操作 DOM。

## B. 本项目自己踩的坑（移植过程中）

### B1. SQL 漏传参数 → 查询静默返回空

``​`js
queryAll(`SELECT ... WHERE save_id = ?`)      // ← 忘了 , saveId
``​`

SQLite 会把占位符绑成 NULL，**不报错**，查询安静地返回空数组。
表现是「商店永远是空的」这种幽灵 bug。

**现在 `queryAll` / `queryOne` 会校验占位符数量，对不上直接抛错。**

### B2. 字段名 camelCase / snake_case 混用 → 属性算成 NaN

`metaRepo.getTemplate()` 返回 camelCase，而 `createPiece` 期望 snake_case，
于是 `template.base_attack` 是 `undefined` → 属性算成 NaN → 绑进 SQLite 时报
「NOT NULL constraint failed」，**报错信息完全指不到真正的原因**。

**规矩：JS 侧一律 camelCase，只有 SQL 列名是 snake_case。**

### B3. 模板字段（code / glyph / 职业）没存进表

`save_heroes` 只存了 `template_id`，战斗和羁绊都需要 `code` / `glyph` / 职业。
解法：`listHeroes` / `getHero` **JOIN** 模板表与职业表，不要冗余存字段。

### B4. `resetBoard` 把格子也删了

棋盘的 64 个格子是提前建好的，重开战斗时只该删棋子。
结果战斗棋盘没有格子 → 一个棋子都渲染不出来。

### B5. 事件时间戳每回合被「重置」

`ctx.log.t = (r - 1) * T_ROUND` 会让时间戳倒退（一回合的事件时长超过回合长度），
前端按 delta 播放就会出现负延迟。

**回合起点要接在上一回合最后一个事件之后。**

### B6. 暴击倍率跟着等级系数一起涨

5 级马的暴击倍率到 7.3 倍，一击秒掉同级王。详见 `docs/balance.md` 第 1 节。

### B7. 四种功能性大招也乘伤害倍率

一次大招秒掉同级单位。详见 `docs/balance.md` 第 2 节。

### B8. 护盾没有上限 → 无限僵持

「铁壁反击」每 4 回合加一大片护盾，而每回合伤害打不穿 →
40 回合里 90 次攻击有 70 次伤害为 0。详见 `docs/balance.md` 第 3 节。

### B9. 敌方阵容随机抽 → 难度曲线剧烈抖动

抽到「后+王」和抽到「兵+马」强度差接近一倍。改成按章节固定 lineup。

### B10. 敌方等级跟着玩家回合数涨

玩家等级涨得比回合慢，于是第 2 章直接打不过。敌方等级只跟章节走。

### B11. 数组字段名写错导致事件缺字段

`attack` 事件里补 `name: attacker.name` 时，只改到了「闪避」分支，
主攻击分支漏了 —— 战斗日志里攻击者名字一直是空的。
**改事件结构时要把所有 `log.push('attack', ...)` 都过一遍。**

### B12. 浮点数没取整

大招倍率显示成 `×3.4700000000000006`。事件里的数字对外一律 `toFixed(2)`。

### B13. 标签页的 handler 忘了定义

`onSelectHero` 没写 → 「阵容」标签页整个不渲染，而且**控制台报错被淹没**，
截图里看起来「内容没切换」。

**加完 handler 要在浏览器里把每个标签页点一遍。**

### B14. `jj` 会自动进分页器并吃掉输入

本机 jj 的 `jj log` / `jj op log` 输出长了会自动进 less，之后敲的命令被分页器吃掉，
屏幕上还会冒 `invalid digit found in string` 之类的假报错。
**所有 jj 命令一律加 `--no-pager`。**

### B15. `jj bookmark set` 之后忘了推

`jj describe` + `jj new` 只改了工作副本，**`main` 书签还指向上一次提交**，
`jj git push` 会报「Nothing changed」。
推之前先 `jj log --no-pager` 确认 `main` 指向你要推的那个提交。

### B16. 端口 5173 已被本机的 Vite 占用

那个 Vite 绑在 **IPv6 的 ::1** 上，本项目绑在 IPv4 的 127.0.0.1。
浏览器访问 `localhost:5173` 会命中 Vite 而不是本项目。
**默认端口改成 5180，并且打印 `http://127.0.0.1:<port>/` 而不是 `localhost`。**

### B17. `node --test test/` 找不到测试

要写成 `node --test "test/*.test.js"`。且 `package.json` 必须有 `"type": "module"`，
否则 `import` 直接语法错误。

### B18. `node:sqlite` 会打印实验性警告

启动脚本加 `--disable-warning=ExperimentalWarning`。

### B19. jj 拒绝快照大文件

2.4 MB 的 docx 超过默认的 1 MB 上限。
`jj config set --repo snapshot.max-new-file-size 8388608`。

### B20. 文档生成时把别的作业的会话也收了进来

同一个工作目录下还有另外两个作业的会话（JHYY 介绍页、jj 回退作业）。
`tools/build-doc.mjs` 现在会按「cwd 在本工作目录内 **且** 首条提示词命中本项目关键词」
双重过滤。

### B21. `playwright-cli eval` 只接受**单个表达式**

``​`
playwright-cli --raw eval "document.getElementById('btn').click(); 'ok'"   # ✗ SyntaxError
playwright-cli --raw eval "(() => { document.getElementById('btn').click(); return 'ok'; })()"  # ✓
``​`

多语句会被判语法错误，而且**报错只在 stderr 里**，很容易以为「点击没生效」。
写自动化脚本时一律包成 IIFE。

### B22. `playwright-cli` 经过 cmd.exe 时，**带空格的参数会被拆开**

`execSync('playwright-cli --raw eval "some code with spaces"')` 会被 cmd.exe 拆成多个参数，
eval 收到的是残缺的代码，然后打印帮助文本 —— 看起来像「eval 坏了」。

**解法：绕过 shell，直接调它的 JS 入口**：

``​`js
const PW_JS = 'C:/Users/liuzhen/miniconda3/node_modules/@playwright/cli/playwright-cli.js';
execFileSync(process.execPath, [PW_JS, '--raw', 'eval', code], { encoding: 'utf8' });
``​`

### B23. 自动化里**不要用固定 sleep**，要轮询等待

每次 `playwright-cli` 调用本身要 1~2 秒，固定 sleep 会出现两种失败：
「等太久」和「状态还没变就断言」。
而且像 toast 这种 2.6 秒就消失的元素，固定 sleep 之后去看必然是空的 ——
**看起来像 bug，其实是测试写错了**。

用 `waitFor(code, timeout)` 轮询 DOM 条件。

### B24. 升阶是**负收益**

「取大 + 小的 50%」听起来比平均值强，但两个同级棋子合成一个，
**总属性从 2A 掉到 1.5A** —— 玩家白白少一个身位还变弱。
自动通关模拟（`tools/playthrough-sim.mjs`）里表现为：模拟玩家在第 3 章反复卡住，
总战力涨到 10 万还是打不过第 3 章。

改成「合并值 × 等级系数比（1.35）」之后，两个同级棋子合成一个总属性 ≈ 2A，
身位少一个但等级 +1（上限 ×1.35）—— 这才是升级该有的感觉。

**教训：养成系统的收益要用「通关模拟」验证，不能只看单场胜率。**

### B25. 乘算型养成没做「数值取整」

卡牌（`×`）和突破都是乘算，叠几次就会出现 `hp 2475.963176294811` 这种小数。
写进 SQLite 的 INTEGER 列**不会**被转换（INTEGER 亲和性只在能无损转换时才转），
于是小数一路存到底，显示也难看。

现在所有改动属性的地方最后都过一遍 `normalizePiece()`（`src/core/progression.js`）。

### B26. 突破可以无限叠

每次突破把该属性的上限 `× 1.5`，上限也跟着突破次数指数膨胀。
自动通关模拟里，一个 1 级棋子的攻击被堆到了 **38408**。

修法：上限记**绝对下限**（当前值 ×1.05），并且**每个属性最多突破 3 次**。

### B27. 商店可以无限买棋子

没有库存上限时，模拟玩家 45 回合买了 100+ 个棋子，存档膨胀、界面卡顿。

加了 `ROSTER_LIMIT = 24`：买满后接口返回 `ROSTER_FULL`。

### B28. 养成系统的收益要用「通关模拟」验证，不能只看单场胜率

单场胜率（`tools/balance-sim.mjs`）看着没问题，但自动通关模拟
（`tools/playthrough-sim.mjs`）一眼就看出玩家卡在第 3 章 ——
因为升阶是负收益（总属性从 2A 掉到 1.5A）。
**模拟玩家走完整条曲线，才知道养成系统的收益够不够。**

```
